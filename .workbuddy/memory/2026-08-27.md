## 提纲助手会话配置重复注入 bug（根因已定位）
- 现象：进入论文工作台 → 提纲助手会话，发送时同一条消息出现两段配置（重复「配置要求」）。
- 第一段 `## 本次对话的配置要求`：前端 `buildRequirementPrompt`（thesis-config-forms.tsx:296），由 thesis-session-view.tsx:371 的 promptTransform 在 configAttached 为真时追加；发送后 configAttached 置否，不会自重复。在仓库内、可控。
- 第二段 `## 配置要求` + `## 输出要求`（带英文注释 journal paper / figures and tables / 全面均衡地覆盖该领域）：来自 @提纲助手 Skill 自身模板/运行时渲染（或模型按其指令回显）。前端/后端源码与磁盘全文均搜不到该文案，非静态文件、不在本仓库。
- 根因：同一份配置面板被前端走了**两条路**投递 → 双注入。
  - 路径A：`promptTransform`（thesis-session-view.tsx:371）直接把配置拼进聊天消息 → 第一段。
  - 路径B：前端 `buildTopicFileContent`（thesis-config-forms.tsx:392）把配置写成项目根目录 `论文主题.md`（outline 在 :146、writing 在 :271，配置一变即保存）；@提纲助手 skill 读该文件（"读工作目录找主题"类 Agent）后按自身模板重排成 `## 配置要求`+`## 输出要求`（带英文注释，属 skill 格式化，非复制）。
  - 第二段数据来自面板、经 `论文主题.md` 中转、格式由 skill 决定；印证：面板图表值=「有图表」，第二段被重述为「需要图表（figures and tables）」。
- 修复方向：因 skill 本就靠读 `论文主题.md` 拿配置，最干净做法是当消息目标为自带配置模板的 Skill 时，前端在 promptTransform 跳过第一段注入，仅保留 `论文主题.md` 单一交付（方案 A，前端可控、改动最小）。方案 B：改 Skill 侧去掉重复配置。dist 为编译产物需重建才生效。

## 前端改动如何生效（运行方式，已确认）
- thesis-web/packages/app 是 vite 项目：`dev`/`start`=`vite`（HMR 热更新），`build`=`vite build`（产物 dist/），`serve`=`vite preview`。
- 改 src/ 后**server 不用重启**：dev 模式 vite 监听文件自动重新编译（HMR）。但结构性改动（store 删字段、删组件/import）HMR 边界不一定干净，最稳是浏览器**硬刷新 Cmd+Shift+R** 拿全新模块。
- 若看的是 build 产物（dist/），必须重新 `npm run build` + 重新 serve。
- vite 默认端口 3000（被占会自动跳下一端口，如 3001）；本机 3000 常被 opencode 后端/旧 dev 占用，注意区分。
- 默认 node 用 managed 22.22.2：`npm run dev` 即可起；tsgo 未装不影响 dev/build（typecheck 才用 tsgo）。

## 后端启动方式（已确认，关键坑）
- 本项目后端**不是 backend/ 源码**起的服务：backend/ node_modules 连 react 都没装、tui 包也未声明 react，用 `bun ./packages/opencode/src/index.ts server` 会报 `Cannot find module 'react/jsx-dev-runtime'`；且 `bun run --filter @opencode-ai/opencode dev` 报 "No packages matched"（包名是 `opencode` 非 scoped）。实际运行的是**全局 opencode**（`/opt/homebrew/bin/opencode`，homebrew 装）。
- 正确后端命令：`opencode serve --port 4096 --hostname 127.0.0.1`（headless server）。注意子命令是 `serve`（不是 `server`——`server` 会去找 cwd 下的 ./server 目录而报错；`opencode --help` 里可用的是 serve/web/attach）。
- 前端 thesis-web（vite 3000）默认连接 `http://localhost:4096`（entry.tsx:101：`VITE_OPENCODE_SERVER_PORT ?? "4096"`，无 .env 覆盖）。
- CORS：opencode serve 默认放行 `http://localhost:3000`（已 curl 验证 `Access-Control-Allow-Origin: http://localhost:3000`）。无需额外 --cors。
- 认证：server 用 HTTP Basic auth。密码=环境变量 `OPENCODE_SERVER_PASSWORD`（当前 shell 设为 `3.7182818280`，username 默认 `opencode`，fork `server/src/auth.ts:53` 读 env）。前端构造 `Authorization: Basic base64(opencode:password)`（`server-protocol.ts:7-9`，ServerConnection 存 url+username+password，password 为空则不发 auth）。验证：`curl -u opencode:3.7182818280 http://127.0.0.1:4096/` → 200。若前端提示输入服务器凭证：`http://localhost:4096` / `opencode` / `3.7182818280`。serve 重启只要环境变量不变，前端已保存的连接仍有效。
- 之前"进入3000无法加载工作空间"根因：opencode serve(4096) 没在跑，前端 3000 连不上 → 起 serve 后前端硬刷新即恢复。
- ⚠️ fork 源码不生效风险：backend/ 源码未 bun install 完整、跑不起 server，所以当前跑的是全局 opencode（不含 fork 源码改动，如 thesis-config-forms 的 config/路径、promptTransform 清理、主页文案等）。若要 fork 后端改动生效，需先在 backend 跑 `bun install`（react 等可能需补装/tui 未声明依赖需处理）再用源码起 server；否则前端改动(thesis-web)生效、后端逻辑走全局 opencode。
